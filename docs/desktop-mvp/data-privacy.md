## 1. Overview

求职档案（申请、事件、附件、简历快照、待办、已确认的 AI 建议结果）**归用户本机上的桌面档案目录所有**。简历模板与「我的信息」自 v0.4.1 起也归桌面档案所有（#130）。浏览器插件不是权威源：它只在填写时向桌面读取这些数据，并可在用户同意后向桌面投递岗位/填写事件。

没有云账号、没有多设备同步。使用用户配置的云端模型时，必须展示外发范围；不得宣传「装了本地应用 = AI 全部在本地」。

## 2. 所有权与信任边界

| 数据 | 所有者 | 权威副本 | 允许的副本 |
| --- | --- | --- | --- |
| 申请 / 事件 / 待办 / 证据 / 快照 | 用户 | Tauri 后端（`data-service` 库）管理的 archive 目录 | 用户导出的备份文件 |
| 简历模板、「我的信息」、当前模板 | 用户 | 桌面档案（`resume_templates` / `resume_state`，v0.4.1 起，#130） | 填写归档时生成的 **不可变快照**；v0.4.1 以前插件存在 `chrome.storage.local` 的旧副本，导入桌面并确认后清除 |
| 插件旧 `aiConfig.apiKey` | 用户 | 升级前在扩展存储；分片到达后先入桌面 OS 凭据库临时账户，确认后移入正式账户 | **禁止**进入 SQLite、桌面备份、日志或诊断 |
| 邮箱授权码（#331） | 用户 | OS 凭据库（复用 `CredentialStore`，独立 `mailbox:<账号 UUID>` 命名空间） | **禁止**进入 SQLite、附件、备份、日志或诊断；不提供读取授权码的界面命令 |
| 邮箱连接 / 扫描位置 / 待确认信头 / 忽略标记（#331） | 用户 | 本机数据根目录 `mailboxes.sqlite`，位于档案目录之外 | 不随档案备份迁移，不进日志或诊断；确认入档后的原文按证据规则处理 |
| 桌面模型 Key（D11） | 用户 | OS 凭据库：Windows Credential Manager / DPAPI；macOS Keychain | **禁止**进 SQLite、附件、备份、日志 |
| 保存意图 / 绑定 outbox | 用户 | `chrome.storage.local` 新 key | 不得含 Key；绑定项以不可变 `sourceRestoreEpoch` 盖章；恢复后与 current 不符则暂停，信封不得被桌面改写成当前身份 |
| 所有待提交快照字节（在线/离线） | 用户 | 扩展源 **IndexedDB**（SW/offscreen/扩展页） | 完整快照持久化且总哈希 ACK 后才可删除；不得写在页面源 |

写入者：仅 **应用进程**（`data-service` 库）。插件、WebView 子进程、NM host 都是客户端。从未配对时，插件不得把申请档案写进扩展存储冒充桌面库，也不得堆积意图。曾经配对但桌面不可用时，只允许 SaveIntent + IndexedDB 快照暂存，不得显示已保存。

## 3. 目录布局

安装目录 ≠ 用户数据目录 ≠ 缓存目录。档案必须与程序文件分离，避免升级覆盖或卸载误删。

**禁止**把开发机绝对路径写进产品。设置页展示解析后的真实路径（中文/空格用户名）。目录不可写时失败，**禁止**静默改用临时目录。

Windows（Known Folder `FOLDERID_LocalAppData`）：

```text
%LOCALAPPDATA%\ResumePro\
  archive\             current 档案
    archive.db
    attachments\
    snapshots\
    tmp\
    meta.json          archiveId, schemaVersion（不含 restoreEpoch）
  current.json         机器本地指针：archiveDir, archiveId, restoreEpoch
  archives-retired\
  logs\
  cache\               WebView2 用户数据等
```

macOS（`NSApplicationSupportDirectory` / `NSCachesDirectory`）：

```text
~/Library/Application Support/ResumePro/
  archive\  ... 同上结构 ...
  current.json
  archives-retired\
  logs\
~/Library/Caches/ResumePro/     缓存，卸载策略可更激进
```

当前生效的 `restoreEpoch` 只由机器本地 `current.json`（或等价指针文件）决定，不把该指针文件或“可恢复的当前 epoch”放进备份。业务回执中的 `sourceRestoreEpoch` 是历史标识，可以随数据库备份用于只读对账；它不能成为恢复后的当前身份。每次成功恢复/回滚仍新铸当前 epoch，不能从历史回执恢复权限。

WebView 用户数据放在上述 cache/数据根下，不要用安装目录旁的默认文件夹。

相对路径入库；拒绝 `..`、盘符、UNC。附件文件名冲突时加后缀，不覆盖（D09）。

## 4. 敏感分级

与 [字段目录](product-requirements.md#8-逻辑对象与字段目录) 一致，三类：

| 级 | 含义 | 例子 | 存储 |
| --- | --- | --- | --- |
| `public-meta` | 流程元数据 | UUID、stage code、计数、耗时、插件版本 | 可进 DB/日志（日志仍截断） |
| `PII` | 能识别求职者或雇主沟通内容 | 公司、姓名备注、邮件正文、简历快照、地点、发件人 | 可进档案与备份；**默认不进日志**；导出备份必须警告 |
| `secret-forbidden` | 能造成账户接管 | 见下表 | **不得进入业务存储或导出**；AI Key 与邮箱授权码仅允许存 OS 凭据库（旧 Key 的一次性迁移见 §7.4） |

### 4.1 永远不得出现在档案、事件、快照、日志、备份、诊断导出中

- 密码、支付口令
- OTP / 短信验证码 / 邮箱验证码
- API Key（插件与桌面）、邮箱客户端授权码
- Cookie、`Set-Cookie`
- `Authorization` 头及其值
- URL 中的令牌类查询参数（见 §7.1）
- NM host 的机器专属绝对路径（备份排除；诊断可含「已配置/未配置」）
- 网页密码框、`autocomplete=one-time-code` 的控件值

插件填写路径已尽量不扫 `type=hidden|file|button|submit`；桌面留档仍要再剥一层。不确定是否为 secret 时：**丢弃该字段，不得「先存再看」。**

### 4.1.1 已取消：插件设置备份

0.4.0 及更早，插件弹窗的「导出备份」可以在用户两次确认后写入插件自己的 API Key。0.4.1 起插件不再保存简历与 Key，插件的备份导出随管理页一起删除；换机器时用桌面的完整备份（§6，不含 Key）并在新机器上重新填 Key。旧 Key 的一次性迁移见 §7.4。

### 4.2 活模板 vs 桌面快照

- 活模板：v0.4.1 起存于桌面档案（`resume_templates`，#130），用户可随时在桌面「重新导入 Excel」覆盖。插件不再保存副本，填写时经 Native Messaging 读取。
- 快照：填写归档确认时拷贝，之后 **immutable**。无论桌面是否在线，发送前先把完整字节提交到扩展源 IndexedDB；完整持久化/总哈希 ACK 前保留原字节，分片 ACK 不触发清理。见 [产品需求 §8.5](product-requirements.md#85-resumesnapshot)。

## 5. 删除、回收与永久清除

| 操作 | 申请行 | 事件 | 附件 blob | 可恢复 |
| --- | --- | --- | --- | --- |
| 列表归档 `archivedAt` | 保留，列表默认隐藏 | 保留 | 保留 | 是 |
| 回收 `recycleState=recycled` | 保留 | **保留** | **保留** | 是（D12） |
| 永久删除（二次确认） | 删除或墓碑 | 随申请移除 | **仅当引用计数为 0** 才删文件 | 否 |
| 卸载程序 | 不触碰 archive | — | — | 档案仍在磁盘 |

孤立附件检查可在维护任务中列出，**不自动删除**不确定项（D12）。永久删除文案必须写清：不可从本应用撤销；若有备份可从备份恢复。

永久删除正文/附件不等于清除幂等身份：同一事务保留最小消息墓碑（无正文），至少覆盖来源 epoch 的可写生命周期。旧消息重试只能得到 previously_purged，不能把用户删除的记录重新创建。墓碑允许随备份保留，具体保留/清理测试归 D03/D12。

## 6. 备份与恢复

### 6.1 完整备份包含

- SQLite **一致性快照**（备份前 checkpoint 或使用 SQLite backup API，D12 定）
- **整个档案的一致性屏障：** MVP 备份期间暂停业务写入、导入完成提交与永久删除；在同一屏障内取得 DB 快照并复制它引用的全部附件/简历文件到独立 staging，再解除屏障。发布前核对 DB 的每个文件引用均存在且摘要相符，缺失则备份失败，不发布残包。若后续改用不可变文件 pin，须证明同等一致性，不允许只保证 DB 快照一致。实现归 D12。
- `attachments/`、`snapshots/`
- 事件、待办、已提交消息回执（含 sourceRestoreEpoch 等完整历史身份，随 DB；不包含当前指针）
- 简历模板与「我的信息」（随 DB，#130）。「我的信息」可能含身份证号、家庭成员等个人信息。密码、验证码类内容由档案存储层拦截，不会进入档案与备份：导入模板时这类行被剔除（界面会说剔掉了几个），「我的信息」里出现这类内容则整份拒绝保存。
- 非秘密设置（UI 偏好、是否允许浏览器连接）
- `manifest`：格式版本、`archiveId`、`schemaVersion`、文件清单、每文件 sha256。**不含当前生效的** `restoreEpoch`、current.json、机器 IPC 路径或凭据；数据库历史回执按上一项保留。

### 6.2 明确排除

- API Key、OS 凭据副本、任何 auth cache
- 调试日志、诊断包
- 机器专属 native-host 路径、注册表路径
- `tmp/`、WebView2 cache、安装器自身
- 导入任务内存中的 `sourcePathHint`：任务完成/失败/取消后清除，不持久化到 SQLite、事件、备份或诊断。保留安全文件名不等于保留原始绝对路径。

### 6.3 加密

**本地导出的 ZIP 备份不加密。** 导出 UI 必须警告：文件含简历与邮件等 PII，应放在用户自己控制的位置。D15 的可选云备份在上传前默认使用 age v1/scrypt 加密；这不改变本地导出和本机保留副本仍为明文的事实。

#### 6.3.1 备份包含项与排除项（D12 落实）

权威清单在 `desktop/crates/backup/src/exclude.rs`，并且有守卫：档案目录里出现清单没覆盖的东西，它**既不进包也不被无声忽略**，而是记进导出报告让用户看见。手写清单不带守卫必然会漏。

| 进包 | 不进包 |
| --- | --- |
| 数据库的一致性快照（SQLite backup API，不是正在被写的 `archive.db`） | `archive.db` / `-wal` / `-shm` |
| `meta.json`（含 archiveId，不含 restoreEpoch） | `current.json`（机器本地指针与当前 epoch） |
| `attachments/`、`snapshots/` | `tmp/`、`backups/`、`logs/`、WebView 缓存 |
| `settings.json` 里**白名单内**的键（目前只有配对草稿的扩展 ID） | API Key、认证缓存、机器专属 native-host 路径、`ai-settings.json`（桌面 AI 服务商列表：名称、接口地址、模型名；不含 Key） |

恢复到新目录后新铸 `restoreEpoch`；同一个备份恢复两次得到两个不同的 epoch。恢复后 `todos` 的提醒记账（`reminder_state` / `reminder_handle` / `reminder_scheduled_for_utc`）清零并重新登记——那些句柄指向的是原来那台机器上的 OS 计划；`overdue_ack_at` 保留。

**卸载不得删除用户数据目录或用户导出的备份文件**（安装器在 D13 落实）。

### 6.4 写入与失败

写到临时目录，校验哈希后原子改名发布。失败不得覆盖已有有效备份。磁盘满：保留原档案 + 至少一个旧有效备份。

### 6.5 恢复

```mermaid
sequenceDiagram
  participant U as 用户
  participant UI as Desktop UI
  participant APP as 应用进程
  participant P as 插件绑定队列
  U->>UI: 选择备份文件
  UI->>APP: 校验大小/路径穿越/哈希/版本
  APP-->>UI: 预览（申请数/事件数/附件数）
  U->>UI: 确认恢复
  APP->>APP: 在独立 staging 目录完整解压、校验并准备迁移；旧 current 不动
  APP->>APP: 暂停写入，刷新新档案；新铸 restoreEpoch，原子替换 current.json
  APP->>APP: 旧目录登记为 retired 回滚点；不在切换前搬走
  APP-->>UI: 成功；旧目录可回滚
  P->>APP: handshake
  APP-->>P: 同一 archiveId + 新 restoreEpoch
  Note over P: 握手成功；比较绑定队列盖章后暂停
  U->>P: 关联 / 丢弃 / 另存
```

规则：

1. 先预览再确认。
2. 在独立 staging/新档案目录完成解压、路径与哈希校验、迁移验证后才切换；切换前旧目录及 current.json 原封不动。暂停写入并持久化新档案后，以原子替换 current.json 作为提交点；失败保留旧指针。崩溃恢复必须识别提交点，不能组合旧目录与新 epoch。**MVP 不做逐行 merge**。
3. 旧档案保留为回滚点，直到用户显式删除。
4. 损坏、截断、不支持版本、路径穿越：拒绝，**current.json 不变**（旧 epoch 仍有效）。
5. **保留 backup 的 `archiveId`。每次成功切换 current 指针新铸 `restoreEpoch`（UUID）。** 不从备份读取 epoch，不用 `generation+1`。握手 **成功** 并返回新 `(archiveId, restoreEpoch)`。绑定队列盖章不符则暂停。意图无 epoch，恢复后重新候选。
6. 再次恢复 **同一** 备份：再铸新 UUID，与上一次不同（走查 10.8 / 10.12）。
7. 回滚到 retired 目录：视为一次新的指针切换，**再铸** epoch，不复用失败前的值。
8. 握手后写入与 `outbox.reconcile` 外层必须自带当前 `(archiveId, restoreEpoch)`；缺失或不匹配直接拒绝，**禁止**桌面代填。普通写入仅在当前身份校验通过、且 `sourceRestoreEpoch` 等于 current 时，才按消息身份+摘要返回原 `resultId`。旧 epoch 只走只读对账。`not_found` 不代表从未执行，不得自动重写。完整契约见 [产品 §8.10–§8.11](product-requirements.md#810-插件队列saveintent-与-bound-outbox)。
9. 恢复后不得瞬间重放全部待办通知；按产品 §5.4 重新登记系统调度。

存储量粗估（单用户一季）：DB 数 MB；每封 eml/PDF 数十 KB–数 MB；简历快照常见为数十–数百 KiB，产品上限 **2 MiB**（超过则拒绝，走桌面导入）。备份大小 ≈ DB + 附件 + 快照。不在 D01 承诺压缩比。

## 7. 插件采集边界

只记录 **用户主动** 的：保存岗位、确认投递、确认填写留档。不监听全部输入、不装全局键盘记录、不保存整页 HTML、不保存浏览历史、不保存用户未点保存的页面。

### 7.1 URL 脱敏与去重 URL

去掉 `https://user:pass@host/` 用户信息与 fragment。

**始终剥离**（大小写不敏感；写入 `sourceUrl` 与 `dedupeUrl`）：

`token`、`access_token`、`refresh_token`、`id_token`、`session`、`sessionid`、`sid`、`auth`、`authorization`、`api_key`、`apikey`、`password`、`pwd`、`secret`、`signature`、`sig`；`code`、`key` 同样**默认剥离**，只有下述已审核岗位号规则可以例外。

**不存在相邻 token 参数并不能证明安全。** OAuth 回调、密码重置、magic link 常只有一个 code/key。仅当确切 HTTPS host、明确岗位页路径、参数名以及岗位编号取值语法都命中版本化、已审核的站点规则时，才可保留该岗位号；没有规则时删除。规则不得覆盖登录/回调/重置/邀请/认证路径，不根据页面自称“岗位号”、模型建议或用户临时输入自动加入 allowlist。D07 必须用该站点的正反例证明规则，不在 D01 假造实际站点名单。

- `sourceUrl` 与 `dedupeUrl` 使用同一秘密剥离策略；清洗必须在入意图队列、日志或数据库之前完成，不保留秘密参数的原始副本。
- `dedupeUrl` 再移除 `utm_*` 等明确跟踪参数并规范化 host。删除参数后可能产生候选碰撞，因此 URL 只能用于提示，不变成自动合并的唯一身份。

合成例：

```text
无已审核站点规则：
https://jobs.example.com/apply?code=REQ42&utm_source=mail&access_token=abc
sourceUrl  = https://jobs.example.com/apply?utm_source=mail
dedupeUrl  = https://jobs.example.com/apply

https://auth.example.com/callback?code=ONE_TIME_SECRET
sourceUrl / dedupeUrl = https://auth.example.com/callback

https://portal.example.com/reset?key=RESET_SECRET
sourceUrl / dedupeUrl = https://portal.example.com/reset
```

allowlist 正例必须与同 host 的认证路径反例一起验收；未知站点、重复参数、大小写变化、编码参数名、超长值和非法岗位号均须测试。不确定则删除，不以提高去重命中率为由保留凭据。

### 7.2 填写留档

默认事件元数据见 [产品需求 §8.8](product-requirements.md#88-填写留档默认范围)。逐字段值默认关。用户拒绝留档：填表照常，不向桌面发送采集 payload。

D08 实现（可核对）：

- 留档是填写结束后侧边栏里的一张卡片，**从未配对的 profile 不出现**；忽略或点「不留档」= 不存、不发。

### 7.3 回复证据导入（D09）

本节区分本机文件处理与主动联网读取。当前主分支实现、真实账号验收及公开发行状态分别见 [#358 邮箱支持矩阵](mailbox-acceptance.md)；有预设不代表所有账号已验收。以下数据流约束适用于包含对应功能的构建，不能据此声称公开的 desktop-v0.4.4 已包含邮箱接入。用户导入后主动选择的 AI 整理仍按其单独外发确认规则处理。

- **本机文件导入、解析和预览不联网；可选的邮箱连接会联网。** 用户主动连接常见邮箱或学校邮箱后，Rust 后端按用户确认的 IMAP 服务器、端口、登录账号，通过 TLS 或登录前升级的 STARTTLS 建立加密连接，验证服务器证书与主机名，不提供明文或跳过证书验证的回退，不经过本产品服务器或 AI。启动及进程内定时检查先只读取发件人、标题、发送时间、Message-ID 信头，在本机按招聘系统域名、申请公司和关键词筛选；未命中信不保存任何内容，只更新文件夹扫描位置。命中信仅保存信头、入选原因和定位信息，用户点击「存进档案」才下载整封原文并走原有导入流程。连接只用只读 `EXAMINE` 与 `BODY.PEEK`，不标已读、不删除、不移动。界面收到安全错误类别，不收到服务端异常原文或授权码。
- **邮件预览继续隔离远程内容。** WebView 的 CSP（`default-src 'self'; img-src 'self' data:`）本身就挡掉远程脚本、远程图片与跟踪像素。HTML 邮件在 Rust 侧转换为纯文本；正文引用的本机 MIME 图片可按原顺序显示，远程图片不保留、不请求，`javascript:` 链接只作为文本出现。
- **原件留在档案目录。** `attachments/<yyyy>/<mm>/`，安全文件名、冲突加后缀不覆盖、同字节只存一份（`refCount`）。导入后用户把原文件移走或删掉都不影响查看。
- **来源路径不留痕。** `sourcePathHint` 只活在一次导入的参数里；错误提示只有安全文件名与错误码。给界面的结构里没有任何档案路径。
- **导入不是判断。** 导入只写 `evidence_imported` / `evidence_associated` / `association_changed` / `evidence_classified`，从不改申请阶段；`replyClass` 与 `sendMode` 由用户分别确认，界面不因为类型是面试邀请就把发送方式写成人工。
- **可核对**：`desktop/crates/evidence-import/tests/hostile.rs` 集中放敌意输入（路径形状、伪装 MIME、可执行文件、损坏邮件、脚本与跟踪像素、病态标签），断言字节只会落在 `attachments/` 之内、正文里没有任何可执行片段或远程地址。

**邮箱配置识别（#332）**：用户输入完整邮箱地址后按回车或点击「确认并识别」，先查软件内置配置；未命中时才使用系统 DNS 配置查询邮箱域名的 SRV / MX 记录，总预算 3 秒。输入、停顿或离开输入框不会触发识别。DNS 查询仅包含邮箱域名，不包含 @ 前用户名、密码或邮件，不抓取网页、不调用 AI；同域服务器和已收录的标准服务商端点沿用正常连接流程；陌生跨域服务器显示橙色待核对状态，列明邮箱域名、服务器、端口和加密方式，用户按官方教程核对并点击使用此配置后才允许输入凭据。后端在任何 IMAP 连接的套接字建立前再次检查这一确认；确认绑定完整邮箱地址、目标服务器、端口、加密方式、登录账号及客户端标识，修改任一项后不再匹配的确认不能使用。只有用户点击测试连接后才会发送登录凭据。确认随本机连接 JSON 保存，不含密码或令牌。旧版陌生跨域连接未带确认时仍可列出、修改或删除，但不能后台登录；需要先重新核对并测试。MX 仅用于已知服务商线索，不能直接充当 IMAP 地址；Coremail 等学校自建配置不猜测。自动发现及手填配置只留在本机，官方帮助由用户主动点击后在浏览器打开。

邮箱连接信息（含服务器、端口、加密方式、登录账号）、候选信头、扫描游标及忽略状态保存在 `mailboxes.sqlite`，不属于正式证据，不进入档案备份或诊断。忽略只修改本机处理状态，后续重扫不会重新提示；断开并移除账号会清除该邮箱的本机候选、游标与忽略记录，并删除系统凭据库中的授权码，已入档的证据不受影响。更换机器须重新连接邮箱。恢复 / 回滚档案不恢复连接或本机扫描状态；网络任务完成时核对当前 archive ID 和 restore epoch，不把恢复前的下载写入恢复后的档案。

### 7.4 旧插件数据导入（#130 PR 3b / PR 5）

插件升级时先发清单，再分片发送旧模板、「我的信息」及 AI 配置；桌面核对摘要并在 SQLite v5 暂存，必须由桌面确认后才成为正式数据。24 小时未收齐的批次过期并清除分片；同一时间只接受一批。暂存模板与档案是 PII，桌面备份若在确认前执行会包含它们，仍按备份警告处理；确认完成后暂存正文清空，仅保留摘要与状态用于幂等查询。

AI 配置片的 apiKey 是协议唯一允许携带 Key 的位置。桌面接收时将 Key 放入 OS 凭据库临时账户 ai-api-key:import-<importId>，SQLite 只存去 Key 后的 apiUrl、model 和 hasKey 标记。确认成功后 Key 移到正式服务商账户并清除临时账户；拒绝或过期也清除。模板与档案已写入、只差 AI 配置（例如临时 Key 丢失或服务商已满）的批次，用户拒绝时按「已导入、AI 配置未导入」收尾（`imported` 且 `aiConfigDropped: true`）：保留已写入的模板与档案，插件清除旧模板与档案、保留旧 Key，桌面清除临时账户；批次完成后重发的 AI 配置片不会再把 Key 放回凭据库。临时账户删除失败时记下待清理，下次启动重试。凭据库失败时不把该片标为已收齐，确认失败可重试且不会重复导入模板。Key 不得进入日志、遥测、SQLite、桌面备份或诊断导出。插件只有看到 imported 才能清除旧副本；带 `aiConfigDropped` 时旧 Key 不清除。

对已应用模板与档案、尚未完成 AI 确认的批次，拒绝操作会先清理可能已写入的正式服务商及其 Key；清理失败时保持待确认状态，供用户重试。只有清理成功才把这一批记为已导入。

**插件这一侧（PR 5，`link/legacy.mjs`）：**

- 只有本地真有旧数据（非空模板、有内容的「我的信息」、非空 API Key）才握手发送；没有旧数据时不会为此启动 native host。
- 发送前整理：「我的信息」里像密码、验证码的项按与桌面相同的口径先剔除（`profile-fields.js` `stripProfileSecrets`，只报个数，不迁移）；超过 24 KB 或超过 25 个的模板不发送；API Key 为空时不发 AI 配置片。
- 插件本地只记清单（摘要）和阶段，不记分片正文；Key 只出现在发给桌面的那一条 AI 配置片里。
- 确认在桌面「简历」页进行，预览只显示模板名与字段数、「我的信息」项数、AI 服务的主机名与模型，不显示字段值、接口路径或 Key。桌面已有「我的信息」时由用户选择保留哪份。
- 插件只在桌面返回 `imported` 时删除本地旧数据，而且只删已经迁过去的部分；没发出去的模板改存为 `legacyUnmigratedTemplates`，用户可在插件状态页下载 CSV 或删除；带 `aiConfigDropped` 时旧 Key 留在插件，用户可在状态页复制或删除。`rejected` / 失败 / 过期都不删任何数据。

## 8. AI 外发

0.4.1 起插件不再保存 Key，AI 请求统一经桌面发往「当前使用」服务商；旧插件 Key 只在迁移时经 §7.4 进入 OS 凭据库。

#223 起桌面可另设「强模型」，同样只能从已保存的服务商里选。只有插件明确请求强档（`ai.complete` 的 `tier: "strong"`，或 `purpose: "analyze"` 不带 `tier`）时才发往它；没设强模型就退回「当前使用」，响应里的 `tier` 如实写 `default`。强模型那条服务商没有 Key 时直接报未配置，不改用当前服务商的 Key，避免内容发给用户没选的服务商。`analyze` 的超时是 180 秒，其余仍是 120 秒。#283 起强档请求改为流式接收（请求带 `stream: true`）：响应头仍按上面的 180 / 120 秒等；收到响应头之后，60 秒没有任何新内容（推理内容、心跳都算）就判为卡住，一次生成最长 10 分钟。只拼接正文 `delta.content`，推理内容不保存、不进日志、不计入正文大小上限（单独一行超过 4 MB 仍按返回过大处理）；服务商忽略 `stream`、照旧整段返回 JSON 时，按非流式读，整段要在同样的 180 / 120 秒内读完。仍然不自动重试。插件停止等待时，浏览器结束这次请求的 Native Messaging host，桌面在约 0.5 秒内发现连接断开，丢掉这次请求并关掉与服务商的连接（不保证服务商停止计算或计费）。

#224 起插件侧栏的「深度分析本页」发出 `purpose: "analyze"`（不带 `tier`，即强档）。`user` 只有插件在本机生成的页面结构大纲：从不读输入框的值，密码、验证码、`autocomplete` 为密码或一次性验证码的控件整体跳过；手机号、邮箱、证件号、网址、像密钥的文字以及与简历值重叠的文字替换为「〔内容〕」；每段不超过 40 字，每次不超过 40,000 字，最多 3 次。随后的填写匹配是普通的 `purpose: "fill"` 加 `tier: "strong"`，内容与一键填写相同。一次深度分析的分析和匹配合计最多 6 次 `ai.complete`。模型返回的页面说明书只在插件内存里校验和使用，不落盘、不进诊断、不回传桌面；元素编号与网页元素的对应关系也只在内存里，不写进网页。深度分析不触发自动错误报告。

#225 起，说明书要求先点「编辑 / 展开 / 添加」时，插件在侧栏预览动作，用户确认后才在当前页面逐个点击并核验，然后在本机重新生成大纲、再发一次 `purpose: "analyze"`（同样的脱敏规则和长度上限），这一次与第一次分析、随后的填写匹配共用每次 6 次 `ai.complete` 的上限，不会重置。动作本身不经过桌面、不发送任何内容；新增条目的数量由插件按模板记录数计算，不由模型决定。诊断只记动作类别的计划数和完成数、固定的停止原因码和分析轮数，不记按钮文字、网页正文、字段值或网址。

桌面发往服务商的 AI 请求和获取模型请求都带 User-Agent `wangshen-kuaitian-desktop/<版本>`（#212）。发往 opencode.ai 的 AI 请求另带 `x-opencode-session`：每次启动随机生成的一个编号，不含用户信息，只为满足 OpenCode 的要求。获取模型请求不带，别的服务商也不带。

| | 插件填写/解析 | 桌面通知整理（D11） |
| --- | --- | --- |
| 配置位置 | 桌面管理（同右列）；插件不保留配置与 Key。0.4.0 的 `chrome.storage.local.aiConfig` 只在迁移前存在 | Windows：Credential Manager / DPAPI；macOS：Keychain；每个服务商一条（账户 `ai-api-key:<服务商 id>`） |
| 发往 | 插件经 Native Messaging 交给桌面，由桌面发往「当前使用」的服务商；插件没有任何直连服务商的请求 | 用户在桌面设置的「当前使用」服务商；设置页点「获取模型」时另向所填地址对应的 /models 发一次只带 Key 的 GET（Key 优先用刚填的；否则只有地址与已保存地址同源——协议、主机、端口都一致——时才用该服务商已存的 Key。15 秒超时，日志只记主机名，报错只按状态码分类、不回显服务商正文，失败不拦手填）。编辑服务商时接口地址换了协议或主机，该服务商的 Key 自动清除。获取模型属于用户主动的配置动作，只带 Key、不带任何简历或证据内容，因此不走发送前预览。 |
| 内容 | 表单字段描述 + 相关简历分组；密码、验证码类字段与资料不进提示词；表单大时按信封大小分批。保存岗位时的识别只发编号片段，见 §8.4 | 证据正文/片段 + **最少**候选申请元数据；简历解析：用户上传的简历全文（发送前显示发给哪个服务商、主机、模型与字数，用户点「发送并解析」才发出） |
| 确认 | 用户主动点「一键 AI 填写」即同意该次填写外发。点「保存岗位到桌面端」且本地提取不可靠时才会识别一次，网页上列出要发的片段，可以取消；结果要等用户在表单里点确认才写入桌面 | 发送前预览范围、服务商、模型；简历解析同样先确认再发送；可取消，取消不保证对方停止计费 |

共同规则：

- 不把完整档案库送给模型。
- 不把另一条申请的快照当作上下文，除非用户在消歧中选中。
- 模型返回只是建议 JSON；正文里的「忽略以上指令」不得变成工具权限（D11）。
- 网络慢可取消；不自动重复计费重试。
- 失败不影响本地证据与手动阶段。

桌面的 Key **永不**回传给插件。唯一跨边界的一次是旧数据导入（§7.4）：用户升级插件时，旧 AI 配置片里的 Key 只进 OS 凭据库的临时账户，用户在桌面确认后移到新建服务商的账户并删除临时账户；它从不进入 SQLite、桌面备份、日志或诊断导出。

### 8.1 桌面这一次分析，实际发出去的是什么

一次 `analyze_evidence_cmd` 的请求体里，**与用户数据有关的只有这些**（另外还有模型名、系统提示词和 JSON 格式要求这些包装字段）。拼装在 `ai-extract::build_request`；「发出去的东西里没有本机 id」由 `ai_commands_tests.rs` 的 `the_request_carries_labels_and_no_local_ids` 盯着，「预览和真会发出去的那份逐字段一致」由同一文件的 `the_preview_matches_the_request_field_by_field` 盯着：

| 字段 | 内容 | 不含 |
| --- | --- | --- |
| 邮件主题 | 这一封的主题原文 | —— |
| 发件人 | 这一封的发件人地址 | —— |
| 正文 | 最多 6000 字，超出截断并在预览里标明 | 附件字节、截图、PDF |
| 候选申请 | 每条只有公司名、岗位名、当前阶段，最多 8 条（用户手选也是这个上限，界面提前拦） | **申请档案里的 UUID、证据 UUID、投递链接、快照、备注、联系人字段** |
| 候选编号 | `c1` / `c2`…，模型只能用编号回答 | 任何本机 id |

右边一列说的是**申请档案里的结构化字段**：这些字段本身不会被送出去。正文是原样发的，所以邮件正文里自然出现的网址、邮箱签名、电话号码会跟着正文一起走——发送前的预览会把正文开头摆出来，就是让用户先看清楚这一点。

Key 只在 `Authorization` 头里，不进正文、不进预览、不进日志、不进备份（`ai-settings.json` 也不含 Key，见 §1 的排除表）。

发送前预览（`preview_analysis_cmd`）是本机计算的，**不发请求**：它显示主机名、模型名、正文字数、是否截断、带上哪几条候选，以及正文开头一段。候选可以当场改，改完会重新算一次预览。

| 证据类型 | 能不能 | 说明 |
| --- | --- | --- |
| `.eml` 邮件 | 能 | 导入时已经抽好正文 |
| 粘贴文本 | 能 | 同上 |

### 8.3 失败与取消

- 超时（60 秒；**简历解析例外，用 120 秒**——解析一份长简历、模型慢的时候可能要一两分钟）、取消、HTTP 错、返回不是 JSON——**一律不写库**，证据和手动分类不受影响。
- 不自动重试：重试等于重复计费。要再试是用户自己点。
- 取消只是不再等这个请求；界面明说**不保证对方停止计算或停止计费**。
- 同一条证据同时只允许一个请求，第二个得到 `AI_BUSY`，不排队；简历解析同一时间也只允许一份在解析，界面说的是「上一份简历还在解析中，等它结束或先取消」。
- 任何失败之后，这条证据的手动分类都照常可用——界面每一条错误文案都会带上这句。
- 一条证据只认一次确认（产品需求 §5.3 第 6 条）。确认过之后面板会禁用确认按钮并说明该去哪儿改，重新分析只会多一条看得见但确认不了的建议。
- 接口地址里不许夹带凭据：带 userinfo（`https://user:pass@host/…`）或查询串里像有 key 的地址**保存不进去**（`ai_settings::credential_in_url`）。否则 Key 会落进 `ai-settings.json`、随每次请求出现在 URL 里，和「Key 只在 Authorization 头里」的口径直接冲突。
- 简历解析没有「确认建议」这一步：模型返回解析成功，结果会**直接存成一个新模板并设为当前**，不像证据整理那样先留一条待确认的建议。用户能核对、能改、能删的地方是「简历」页的模板列表——解析完就在那儿，跟手动导入的模板一样对待。

### 8.4 插件保存岗位时的识别

本地规则已经得到可靠的公司和岗位时，不调用模型。只有公司或岗位缺失、两者疑似填反、候选只是站点标题，或本地候选互相冲突时，才识别一次。请求和填写走同一条路：插件在 offscreen Worker 里组好提示词，以 `ai.complete`（`purpose: "extract_job"`）交给桌面，由桌面发给「当前使用」的服务商。插件不读取、也不保存任何 AI 地址或 Key。

一次请求的用户内容只有编号片段：`id`、来源标签、角色、短文本。角色限于公司、职位标题、招聘元数据里的岗位工作地点、页面标题。每段不超过 160 字，最多 8 段。页面链接由本地 URL 脱敏规则生成，不放进请求，也不交给模型编写。

不发送：整页 HTML 或正文、投递表单里已填写的姓名 / 电话 / 邮箱 / 证件号、简历和「我的信息」、Cookie、凭据、带查询参数的原始 URL。片段文字里只要像链接（带 `://`、查询串，或 `jobs.example.com/apply` 这样的常见小写域名加路径）或像凭据（`token=`、`api_key:` 这类），整段不发。这是按文字特征判断的；兜底仍是只发最多 8 段短文本、字段必须能在片段里找到原文。意向工作地点、期望工作地点、面试站点不算岗位地点，模型提到了也不会保存。

识别期间，网页上的面板写明发往桌面当前使用的 AI 服务，列出这几段文字，并提供「取消识别」；Chrome / Edge 原生侧栏同时显示正在识别和发送的段数，也能取消。面板不显示接口地址或模型，插件没有这些信息。「保存岗位到桌面端」按钮下方在点击前就说明页面信息不全时会外发岗位文字。

模型只能返回 `company` / `title` / `location` 和对应片段编号。字段必须与所引用片段的全文一致（职位标题可以是「你正在投递职位」后面的全文）；独立、完整、以「公司」或「集团」结尾的页面标题也可作为公司证据，含招聘或岗位文字的标题不能当公司。对不上就丢弃。

桌面不可用、AI 未配置、超时（AI 请求等 25 秒；Worker 本身没反应时 30 秒后放弃）、取消、格式错误或没有证据时，打开可编辑表单并说明原因，不自动再请求，也不静默保存猜出来的值。AI 未配置时表单里多一个「打开桌面 AI 设置」。桌面版本太旧、还不认识这种请求时，提示更新桌面。取消和超时只是不再等这次请求，和 §8.3 一样不保证服务商停止计算或计费。

- 升级覆盖 INSTDIR，不碰 `archive\`；迁移前自动备份 DB（D03/D12）。

## D15 手动 WebDAV 云备份（#306）

桌面仅在用户保存配置并主动执行备份、测试连接、查找或下载时，直接访问用户配置的 HTTPS WebDAV；不经过项目中转。默认 age v1/scrypt 加密，明确确认后可选明文。元数据公开时间、大小、档案/设备/备份 UUID、包哈希和加密格式；不含业务数量、岗位/公司或附件名称。口令丢失无法恢复。应用密码建议用坚果云第三方应用密码，秘密仅在 OS 凭据库中，前端只有写、删和存在布尔值。

`settings.cloudBackup` 仅含非秘密连接和策略，保留配对设置并以临时文件替换写入。它不加入 `PORTABLE_SETTING_KEYS`。新机器按根目录发现档案和设备，不需要旧设备 ID；发现不授予删除权。目录完整性未获真实服务商证据时保留策略继续失败关闭。

本机 `cloud-backup-state` 保留上一份成功明文包与一个待重试候选；界面显示具体路径。云端加密不等于本机加密。下载工作在 `cloud-backup-work` 的私有任务目录，传输 SHA-256、age 最终认证、内部清单和文件哈希全部通过后才有预览。后台确认令牌绑定任务和同一文件哈希，有效十分钟、单次消费；新选择、取消、过期和重启失效，临时明文正常结束时清理，异常退出于下次启动清理。

确认恢复复用本地恢复切换与回滚实现，保留 archiveId，产生新的 restoreEpoch，旧插件 epoch 拒写。任何恢复或回滚前先持久化 `automaticEnabled=false`、`requiresConfirmation=true`；设置写入失败则不切换。#307 必须遵守该门禁，不得迁移设备 ID 或自动重新开启。

完整操作说明见 [用户指南](../user-guide.md#手动坚果云备份与恢复)，证据与未验收项见 [D15 手动闭环验收](d15-manual-cloud-acceptance.md)。普通本地 ZIP 导出仍不加密。


## D15 可选自动计划（#307）

非秘密开关仍由本机 `settings.cloudBackup.automaticEnabled` 与 `requiresConfirmation` 控制；计划/槽位 claim、绑定摘要、业务指纹基线、重试时间及估算预算存入既有私有 `cloud-backup-state/state.json`，默认值向后兼容。上述内容不进可迁移设置或云端元数据，也不触发使用统计。详情见 [自动计划实现与验收](d15-automatic-cloud-backup.md)。

先持久化槽位 claim 再创建候选，后台每约 30 秒检查，只在应用进程内运行。固定 UTC 偏移决定日期，系统时区变化不自动改计划；时钟回退暂停，启动/唤醒错过时间只提示。恢复/回滚先持久化关闭开关并取消自动任务，新的 archiveId/restoreEpoch 绑定要求先完成手动备份再明确启用。云恢复、手动上传及正常业务继续通过原有互斥路径。

指纹从同一 SQLite 快照按表/列/类型和有序行计算，再结合已验证包清单中数据库以外的条目摘要；排除 SQLite 页布局、包 createdAt、任务 ID、ZIP 与 age 随机字节。临时快照块与迁移执行时间、OS 提醒句柄及其共用的待办 updated_at 不参与；业务记录时间、序号及持久回执/删除墓碑影响恢复与幂等语义，保守纳入。只在远端发布确认后更新基线。

预算从首次上传尝试起按连续 30 天计数，实际 PUT 前预记完整包体/元数据大小，结果不明也计入；手动操作计数但不因自动预算暂停被阻止。能力探测、网络协议及对账下载不在估算内，不能作为服务器余额。80% 告警，用户可选择超出暂停或仅提醒。认证/权限/空间/大小等需人工处理；网络/限流/5xx 复用候选先对账，最多 3 次上层重试，尊重更长 Retry-After；清理失败保留成功状态。


### 7.4 网页邮箱主动保存（#333／#357）

插件在 QQ、163 / 126 和 Gmail 邮箱页面显示侧栏保存入口，仅检查活动标签页 URL，不预读邮件，也不记录浏览邮件的历史。用户在侧栏「邮件」栏目点击保存时才读取当前单封邮件，并通过邮箱只读下载入口取得原件。已有登录会话由浏览器用于邮箱请求，插件不导出 Cookie，不保存会话 URL，也不把登录信息传给桌面。新增 `scripting` API 用于 QQ 按需导出，已有 host 权限范围不变。

原件（含邮件内嵌附件）仅通过本机 Native Messaging 传给桌面，按现有邮件规则去重入档，不发送给产品服务器或 AI。超过 25 MiB 不截断保存。读取期间切换邮件则拒绝保存混合结果。取不到原文时明确说明只保存发件人、标题、页面显示时间及正文，只有再点击「保存网页摘录」才入档；原件和附件未保存，摘录不伪造邮件编号，可能无法与之后的原件自动去重。

邮件内容不进入插件持久队列或浏览记录。插件侧仅请求期间持有原文；未确认摘录在侧栏内存中，取消或切换标签页时清除。桌面未完成块仅保存在进程内存，最多 4 个上传 / 64 MiB；15 分钟无活动的状态在下一次邮件请求时清理，退出进程即丢弃，成功后清空原文字节。完成归档的邮件与其他回复证据一样保存在本机档案，可随用户主动导出的备份或配置的云备份包含在包中。

QQ 新版在你点击侧栏保存后，通过限定的原生“导出为 eml 文件”菜单动作取得当前邮件编号；仅在该同步动作内临时拦截新窗口调用并立即还原，以避免额外弹出下载窗口。适配函数只在本次请求运行，结果由浏览器直接回传，不安装常驻页面监听，不预读邮件、不遍历全局邮箱数据；原件仍由隔离内容脚本通过同源请求读取。

Gmail 适配在点击后读取当前账号控件的邮箱标识和单封邮件的页面标识，仅用于本次目标校验；不将账号控件内容、会话 URL 或页面邮件编号发送桌面或记录到日志。多封展开时拒绝猜测，传输原件前和确认摘录时都重新核验当前目标。临时校验只在页面内存保留一份，校验后消费，取消、页面导航和最多五分钟到期时释放，并清理监听和计时器。支持 Navigation API 时直接监听同文档导航；旧引擎仅在临时目标存在时检查 URL 是否变化，不轮询邮件内容。原始邮件页从同源、同账号路径的仍打开来源阅读页核对实际邮箱身份，来源关闭、重载、换账号或不可访问时拒绝下载，不把收件人冒充登录身份。使用已观察并验证的 Gmail 整封只读下载路由，从页面单封编号定位原件；不读取私有全局邮箱状态，也不自动点击网页菜单。Gmail 原件可能重定向至精确的 `mail-attachment.googleusercontent.com` 域名；请求放在随包临时子页面，其 CSP 仅允许 Gmail、Googlemail 及该附件域名，读取响应前还核对最终账号路径与单封编号。父子消息核对来源、扩展源与随机请求编号，结束时移除子页面和监听；Google 签名 URL 不输出或持久化。下载不可用时提供完整正文摘录确认及原始邮件页指引；截断正文拒绝作为完整摘录。

实现与真实账号验收边界见 [网页邮箱保存](webmail-save.md)、[Gmail 保存](gmail-webmail-save.md) 和 [#358 矩阵](mailbox-acceptance.md)。Gmail #357 在 PR #419 中有个人 Chrome 页面的部分真实验证，尚未成为公开 v0.4.4 的已交付入口，不由此推断 Workspace／Googlemail／Edge 已验收。本轮不新增 Outlook 支持或 OAuth／Graph／Gmail API 权限；来源为 Outlook 的标准 `.eml` 仍按通用导入处理。

### 邮件附件查看（#333）

桌面在用户查看已入档邮件时从本机 `.eml` 解析附件清单，点击文件后才向界面交付该文件附件的预览内容；正文内嵌图片在查看该封邮件时从原件按需读取。没有后台下载、AI 请求或产品服务器外发。PDF 用本机 pdf.js 逐页渲染、图片用受控 data URL；正文只交付文字和本机 MIME 图片引用，不传入邮件 HTML，不把附件中的 HTML / SVG 当作可执行网页内嵌。发给 AI 的证据范围不因新增附件查看而自动扩大。

XLSX 在 Rust 中复用现有 Excel 解析器及 ZIP / XML 预算校验，界面只接收单元格文字、坐标及工作表名称。单文件预览上限 5 MiB、ZIP 总解压预算 32 MiB；显示前 500 行、50 列，并限制单元格和累计文字长度。截断有明确提示；不计算公式、不执行宏、不读取外部链接，完整格式仍可用系统程序打开。正文最多交付 64 KiB 文本及 16 处本机图片引用，单个 PDF / 图片内预览不超过 8 MiB；超限原件仍可另存为。

用户选择另存为时，经原生文件选择器将解码后的副本写到指定位置；取消不写文件。系统打开只接受实际字节类型与扩展名匹配的 PDF、PNG / JPEG / GIF / WebP 和 XLSX；其他类型只允许另存为，不交给系统启动。打开前在后端再次检查，不信任界面的标志。系统打开只交出缓存中的私有副本，不修改档案原件。同名同内容副本复用，重新打开前检查副本仍与原件解码字节一致；最多 16 份、64 MiB，满额时不删除近期仍可能使用的文件，提示另存为或稍后重试。下次打开时清理一小时未使用的副本，正常退出时尝试删除，启动时在独占缓存锁内重试清理异常退出遗留的本功能目录；占用或清理失败时明确提示。临时副本不进入档案备份；用户另存出的文件由用户管理。

QQ 新版导出适配通过新增的 `scripting` API 在用户保存时按需执行，绑定发起请求的顶层 browser documentId，浏览器直接返回执行结果，不使用网页可伪造的 DOM 回复。邮件内容与页面状态仅在本次内存请求内核对，不写入日志或持久存储。XLSX 类型通过有预算的 ZIP 目录和 OOXML 内容类型验证，避免成员排序造成误判；类型校验不读取单元格，不与内预览 5 MiB 上限混用。桌面正常退出在 `RunEvent::Exit` 显式清理临时附件，失败仍由下次启动清理兜底。

网页摘录的确认与重试都在用户点击时核对目标。QQ／163／126 现在同样只在内容脚本保留一份最多五分钟的临时快照和随机标识，绑定标题／发件人／时间／正文、页面编号、来源文档与节点；同 URL 换邮件、内嵌页重载也拒绝旧提案。此校验只读取当前阅读区域，不重复下载原件，不自动检查服务器邮箱。目标未变时允许再次确认重试，成功／取消／失效／导航／新捕获释放快照。随机标识和匹配信息不传给桌面或持久存储，原件入档协议不变。

### 招聘通知的永久删除

通知回收站支持逐条永久删除，二次确认展示标题与范围，确认绑定 archiveId、restoreEpoch、通知 ID 和原件摘要。执行时重新检查回收状态，已恢复、已切换档案或目标不匹配则拒绝。数据库事务删除通知、回收标记与 AI 建议，保留最小提交墓碑；申请、既有进度和待办不回退。

仅对剩余实际引用数为零的原件清理文件，其他通知（包括回收站记录）共用的原件保留。数据库先提交、文件后清理；失败保留零引用元数据并提示附件维护重试，不宣称文件已删除。限制在当前档案附件目录内删除，不跟随目录符号链接越界。已有备份、用户另存副本和邮箱服务器上的邮件不受影响。新的主动导入仍可创建新通知；已完成插件上传的旧回执重试只返回已删除，不恢复旧通知。详见[实现与验收](notification-trash-delete.md)。
