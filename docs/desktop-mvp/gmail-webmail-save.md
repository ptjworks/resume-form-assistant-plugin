# #357 Gmail 网页保存

## 状态与范围

实现基于 #333 已有的插件侧栏、Native Messaging 分块传输、原件／摘录入档和去重。新增 Gmail 页面适配、受限原件下载及临时目标重核，不改桌面协议，不增加扩展权限，也不接入 Google OAuth 或 Gmail API 自动收信。

**2026-10-31：已在 macOS 的 Chrome 155、个人 Gmail 英文页面完成原始邮件页、普通会话中的单封回复、完整正文页、会话多封拒绝和重复保存验证。** 原件与 Gmail 原生下载逐字节一致，内嵌附件也一致；桌面通知可见原信、回复及附件清单，手动导入同一原件也能去重。Googlemail、Workspace、Edge 及多账号切换尚无真实验收证据，不由本次结果外推。完整场景与限制见下表。

## 使用边界

- 入口仅依据活动标签页 URL 启用，支持 HTTPS 的 `mail.google.com`、`mail.googlemail.com` 下桌面版 `/mail/u/<数字>` 路由，兼容结尾斜线；手机页、登录页、其他域名、仿冒后缀不启用。不在打开侧栏或刷新标签信息时读取邮件。
- 普通阅读页识别一个可见阅读区域与一个展开的单封卡片，分别读取该卡片的发件人、显示时间、正文及所属会话标题。折叠邮件、隐藏旧阅读窗格、正文伪造的卡片或工具栏不参与目标识别。
- 多封同时展开时要求用户只展开要保存的那封，不猜最新邮件、不自动读取整段会话，也不自动收起或展开邮件。若页面不能只展开目标，可从目标邮件菜单打开“显示原始邮件”；该页还需验证来源阅读页的账号，不能验证时手动下载导入。未知结构、账号标识缺失、邮件编号冲突等情况拒绝猜测，提示刷新或手动导入。
- 点击时从 Gmail 页面的账号控件取得账号邮箱，用于本次请求前后核对，不发给桌面、日志或产品服务器。页面邮件编号只作为瞬时来源定位，不伪造成 RFC Message-ID。
- 只有不透明 `msg-a` 编号、没有可验证十六进制邮件编号时，不猜测编号映射；原件不可用则提供明确的摘录确认。
- Gmail 截断正文时，不把截断部分当完整摘录。原件下载成功仍可正常保存；下载失败时提示原始邮件页或手动导入。“查看完整邮件”页有独立适配，只取单封正文，排除页面工具和附件操作区。

## 原件下载

不点击页面菜单、不遍历 Gmail 私有 JavaScript 数据，不导出 Cookie。使用实际观察并完成字节核对的 Gmail 原生整封下载方式：

1. **普通阅读页／完整正文页**：以当前唯一单封邮件的编号定位原件。接受匹配的原生下载链接，也可使用已经真实验证的只读路由 `/mail/u/<账号序号>/?view=att&th=<单封十六进制编号>&attid=0&disp=comp&safe=1&zw=`。十进制 `msg-f` 编号转换为十六进制，存在另一编号时必须一致。未取得可验证单封编号时不生成请求。
2. **原始邮件页**：识别 `view=om` 页面及其实际提供的下载链接，同时从仍打开的同源、同账号路径的来源阅读页取得原生账号控件（完整正文页使用其已适配的账号栏）。下载前后重核邮箱身份及来源文档；来源关闭、重载、换账号、跨域或无法取得 `opener` 时拒绝下载，指引回到普通／完整正文阅读页，或手动下载导入。不把邮件头中的收件人当登录账号，不从 HTML／textarea 重建 MIME。
3. 验证当前邮箱形式的 `authuser` 后，统一规范成相同账号路径的数字序号，页面和下载器使用同一语义；其他邮箱或账号序号拒绝。已验证固定下载路由放在候选首位，保留在最多三次尝试的预算内，不被多个原生链接挤出。起始地址仅允许 Gmail／Googlemail 的限定账号路径、只读参数及整封邮件模式，拒绝其他账号／邮件、动作参数、重复参数和单附件链接。原生无结尾斜线地址先规范化，避免无意义的同源 301。
4. Gmail 实际将原件重定向至 `mail-attachment.googleusercontent.com`。下载在随包临时扩展子页面进行，子页面的 CSP `connect-src` 仅允许 `mail.google.com`、`mail.googlemail.com` 和该精确附件域名，约束包括重定向在内的网络目的地。读取响应前，再核对最终 URL 的账号路径、单封编号和整封模式。浏览器自行附带已有登录会话，不设置或读取 Cookie 请求头。
5. 父子页面消息核对来源窗口、扩展源和随机请求编号；返回值只含状态及原文字节。请求结束移除子页面和监听，20 秒请求超时、25 秒桥接期限；沿用流式 25 MiB 上限及邮件格式校验。HTML 预览、登录页和错误页不能冒充 `.eml`。
6. 普通阅读页取不到原件且正文完整时，用户再次点击“保存网页摘录”才入档，明确缺少原件及附件。截断正文或原始邮件页下载失败则提示手动下载导入，不保存部分正文或整个原文展示页面。

会话参数、Google 签名下载地址和邮箱内部编号只在本次页面请求中使用，不输出到桌面、日志或持久存储。邮件原件本身仍保留其原有 RFC 邮件头。

## 切换与临时状态

- 捕获时固定页面、账号控件、单封标识、标题、正文、DOM 节点与路由；下载前后均核对，传输前再做一次消费式核验。
- 页面内只保留一份临时目标快照，给侧栏返回随机的一次性标识，标识不含账号、正文、会话 URL 或邮箱内部邮件编号。
- 原件传给桌面前以及用户确认摘录时，侧栏向当前顶层内容脚本核验临时标识，再确认活动标签页仍一致。相同 URL 下换账号、换邮件或重新加载页面也不能复用旧标识。
- 下载前后的检查不消费标识；最终接受会消费。Gmail 摘录传输失败或桌面拒绝时清除已消费的旧提案，提示检查连接并重新点击保存，重新读取、确认后才能重试；不复活旧标识，也不将连接失败误报为邮件切换。取消摘录仅释放快照，不重新读取邮件。新捕获覆盖旧快照；pagehide、hashchange、popstate 以及支持 Navigation API 的同文档导航均释放。旧引擎只在临时目标存在时每 250 ms 比对 URL，不轮询邮件内容；URL 变化即释放。临时目标最多五分钟，消费、取消、失效或到期时移除监听及计时器。捕获与重核还同步检查 URL，拒绝导航后复用。目标改变时丢弃提案，要求重新保存。
- 桌面沿用既有 archive ID／restore epoch、分块摘要与完成回执；只有实际持久化成功才显示保存完成。原件幂等去重；摘录保持独立来源，不承诺与以后原件自动合并。

## 本轮审查修复与验收边界

- A6／B2：本账号邮箱形式 authuser 在页面侧核对后规范为数字路径序号，下载器不再拒绝页面已认可的链接；没有证据将旧失败回退等同于跨账号取错信。

## 摘录重试与错误归因

QQ／163／126 的摘录使用可重复核验的临时目标：桌面暂时不可用或传输抛错时，当前提案保留；再次点击“保存网页摘录”先核对阅读区域、标题、发件人、时间、正文、邮件编号、来源 URL 和节点引用。目标未变时直接重试，不重复下载原件、不自动重试；同一 URL 下换信或内嵌阅读页重载则清除旧提案，要求重新读取。切换标签页后不恢复旧提案，桌面档案切换时也清除提案并要求重新读取、选择申请。

Gmail 的已消费目标继续清除，必须重新读取并再次确认，避免复用旧快照。确认阶段区分邮箱页面核验与桌面发送：活动页查询或内容脚本消息失联时，提示页面可能刷新／切换并要求重新读取，不发送给桌面；只有发送阶段失败才提示检查桌面连接。

新增 4 项测试，覆盖三个非 Gmail 服务商的返回失败与消息异常后直接重试、档案变化清除、切页后迟到失败不能恢复旧提案，以及 Gmail 校验消息异常不联系桌面且提示正确。既有 Gmail 失败后重读确认测试保持通过；本轮完整插件回归 2,061 项、邮箱定向 125 项、侧栏专项 36 项、类型检查及 23 项发布清单检查通过。

## 非 Gmail 摘录的重试目标校验（B6）

将现有临时目标管理扩展到 QQ／163／126 摘录。捕获时返回随机标识，只在内容脚本保留一个有期限的目标快照；与 Gmail 共用取消、新捕获、导航及五分钟过期清理。快照绑定发起请求的顶层文档、实际阅读文档、正文节点和来源地址，兼容 QQ／网易内嵌阅读页；相同文字的新节点或 iframe 重载也不能复用。

非 Gmail 每次确认（含失败后的重试）发送不消费目标的 WEBMAIL_CHECK，重新检查当前阅读区，不下载原件；验证通过后才发送旧提案的已确认字节。失败保留仍有效的目标，成功／取消时释放；若目标变化、失效、缺失或消息通道失败则拒写并清除提案。Gmail 仍在确认时消费一次性目标，传输失败后需重新读取。

新增 11 项回归，包括三个服务商的同 URL 内容／节点变化、多阅读区歧义、QQ 内嵌页面重载／换会话、QQ 新版相同文字不同编号、网易 js6 内嵌正文重载，以及真实适配器与侧栏联合验证“首次失败 → 同 URL 换信 → 重试拒写”。缺少目标和内容脚本失联均不得绕过校验。最新完整插件回归 2,061 项、邮箱定向 136 项、类型检查与发布清单检查通过；无后台预读、无额外网络校验，不改变原件保存协议。

## 原件的最终核验与校验异常兜底

QQ／163／126 下载完成后的原件现在也携带临时目标标识，绑定发起请求的顶层文档及实际阅读文档；交给桌面前，侧栏统一发送消费式 WEBMAIL_VALIDATE，再核对活动标签页。正文／阅读节点变化、同 URL 换信、内嵌阅读页重载、缺少目标或消息失联均阻止传输。原件目标不会随 Native Messaging 发给桌面；下载完成时的既有校验保留，未改档案协议。摘录仍按 Gmail 一次消费、其他服务商失败可重核重试的规则处理。

目标校验内部捕获 DOM／页面读取异常，释放临时目标并返回 changed；内容脚本的校验、丢弃和捕获分发增加同步异常兜底，捕获异步失败也清理临时状态。调用者总能收到明确失败结果，侧栏恢复可操作状态，不将未通过校验的内容发送入档。

新增 6 项回归，包含三种非 Gmail 原件的一次性校验、实际适配器＋侧栏的同 URL 换信阻止传输、最终校验时切标签、校验抛错／消息失联拒写、DOM 异常释放可重用目标、内容脚本消息仅响应一次且支持重新捕获。最新完整插件回归 2,244 项、邮箱定向 142 项、类型检查和 23 项发布清单检查通过；这些新增情况为合成页面自动化验证，未替代真实邮箱验收。
