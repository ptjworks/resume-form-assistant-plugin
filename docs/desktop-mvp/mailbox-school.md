状态核对（2026-11-01）：基于 #331 的扩展已于 2026-10-27 随 PR #348 合入主分支；#332 仍打开。每家真实账号及至少一所学校的真实登录尚未完整验收，预设和配置识别不代表已实测连通。Gmail IMAP 最初在登录前 TLS 链路失败；同日网络恢复后，个人账号已完成发现、确认入档、附件及重复扫描／重启和手动去重的部分实测（E04），11 月 1 日补验中文垃圾邮件文件夹扫描／确认下载，用户确认两封分别经过只扫描和下载后均仍未读、仍在垃圾邮件中（E05）；其余账号和失败场景未测。当前矩阵、发布边界与后续动作见 [#358 邮箱验收记录](mailbox-acceptance.md)。下文保留开发和审查历史。

## 用户流程

1. 招聘通知 → 连接邮箱 / 设置 → 邮箱，输入地址。
2. 在地址框按回车或点击「确认并识别」后，常见邮箱与已知学校填写本地配置；未命中时查询 DNS，总预算 3 秒。输入、停顿或离开输入框不会触发识别。DNS 返回期间允许手填，迟到结果不会覆盖另一邮箱或手动修改。
3. 核对或修改服务器域名、端口、TLS / STARTTLS、登录账号；默认完整地址，可以改为学校要求的短用户名。网易企业邮等可勾选发送客户端标识。不支持明文或跳过证书验证。
4. 根据对应教程填写授权码 / 应用专用密码 / 学校要求的密码，点击测试连接并保存。失败不保存。成功后复用 #331 最近 30 天、运行期间增量检查、先信头待确认、确认才下载原文的流程。
5. 连不上可点“改用导入邮件文件”，进入招聘通知页导入 .eml；学校可能没有开放 IMAP、要求校园网或毕业后回收邮箱，属于尽量支持。

## 识别与维护

- 内置精确域名预设：QQ / foxmail、163、126、Gmail / googlemail、iCloud / me / mac、新浪（com / cn 及 vip）、搜狐、阿里个人邮箱、139。
- 学校预设首批收录清华 `mails.tsinghua.edu.cn`（学生）与 `mail.tsinghua.edu.cn`（教工），分别使用同名主机、993/TLS，要求客户端专用密码。配置来自学校文档，尚不代表真实账号连通验收。
- 未命中时，以系统 DNS 配置查完整邮箱域名的 `_imaps._tcp` / `_imap._tcp` SRV；按优先级与权重选择，显式禁用不回退到同一服务。查询 MX 只用于腾讯 / 网易企业邮的服务商线索，IMAP 地址来自已知映射，绝不直接使用投递服务器。学校自建 Coremail 不根据名称猜主机。
- 查不到或超时展开手动配置；不抓网页、不调用 AI。查询只使用域名，不包含完整邮箱地址、登录账号、凭据或邮件。
- DNS 识别是建议，服务器始终可见、可改，点击测试连接才登录。已保存配置仅在本机，凭据只在系统凭据库。
- 已有账号通过“修改连接 / 更新凭据”载入真实保存配置；同配置更新凭据保留游标，修改连接配置原子清除该账号的候选 / 忽略 / 游标，避免旧 UID 指向另一个邮箱。正式入档邮件不受影响。
- `mailboxes.sqlite` 增加可空 connection JSON 列，旧账号在读取时沿用原先预设；档案 schema 和备份格式不变。
- Outlook / Hotmail / Live / MSN 的个人域名明确提示微软授权另做，不用应用密码反复尝试。

## 2026-10-26 审查修复

- 同一邮箱域名内修正地址时保留手填、已保存或 DNS 已识别的服务器、端口、加密方式及客户端标识。默认登录账号跟随新邮箱地址，手填的登录账号保留，并提示用户核对；实际账号变化清除旧凭据，明确显示“原凭据已清除，请重新填写”。只改大小写或首尾空格不清除凭据，不打断同地址的查询结果。
- 切换域名重新配置，避免把上一家邮箱的主机带到新邮箱。保留配置时不自动重查覆盖，用户仍可主动点击「确认并识别」重新查询。
- 配置控件同时监听 input / change；手动编辑会取消未执行的查询和迟到的查询结果，兼容下拉框与复选框只触发 change 的路径。
- 合入 #331 的 `1a9d313` / `d83f896`，保留登录时只验证必需收件箱、有限重试预算、未实际读取不消耗重试次数、部分完成不更新时间为完整成功等修复。重试状态的本机写入仍核对连接配置并使用短档案锁。

本轮本机验证：邮箱模块 40 项、邮箱宿主 13 项、完整界面 372 项（其中邮箱专项 40 项）、纯逻辑 239 项通过；类型检查、生产构建与 git diff --check 通过。真实账号验收边界不变。

审查意见取舍：单行配置损坏使账号列表失败属于可用性增强，当前正常写入有校验，未找到正常流程生成损坏数据的路径；没有将其认定为 P1。SRV 明确禁用时不通过 MX 猜测同一服务。工作流固定版本与 main 一致，属于仓库迁移配置同步。自动发现的编辑区可折叠，但服务器摘要仍可见；不据此认定凭据泄露。archive_worker 本身不持档案锁，未发现所猜测的嵌套锁。

## 2026-10-26 识别由用户确认触发

按用户反馈取消 500 毫秒计时器和 blur 触发，常见邮箱预设也在按回车或点击地址旁「确认并识别」后才填写。键盘回车只执行配置识别，阻止表单隐式提交；组合输入确认、重复按键不额外触发，同地址飞行中的查询合并。提交不完整域名时就地提示完整地址，不查询 DNS。手填、同域配置保留及迟到查询隔离保持原语义。

本轮只调整识别操作；当时 DNS 跨域信任确认仍在讨论；该项现已按用户批准落实（见下节）。帮助打开失败的提示按用户要求不改。

该轮验证：完整界面 376 项（邮箱专项 44 项）、类型检查及生产构建通过。本轮没有改动 Rust 连接与帮助打开实现。

## 2026-10-26 陌生跨域服务器确认

已修复 DNS SRV 自动配置到陌生主机后可直接提交凭据的路径。

- 前端将原邮箱域名与目标主机按标签边界比较，明确收录的服务商主机只接受固定 TLS 993 端点。陌生跨域结果显示单个橙色待核对卡片，列明邮箱域名、服务器、端口和加密方式，并提示到学校信息中心 / 邮箱服务商官网核对。未知学校不编造官方教程链接。密码输入和测试连接在点击「我已按官方教程核对，使用此配置」前禁用，直接提交事件也被拦截。识别结果携带的确认字段不被采纳。
- Rust 的 connect_configured 在建立套接字前执行相同授权规则，覆盖测试连接、后台扫描、候选下载与重连。缺少确认时返回安全的 EndpointConfirmation 类别，不访问陌生主机，不发送凭据。结构校验不要求确认，避免旧账号不能列出 / 修改 / 删除。
- 确认绑定规范化邮箱、目标主机、端口、加密方式、登录账号及客户端标识，保存于本机连接 JSON 的可选 endpointConfirmation 字段。变化后旧确认不再匹配。旧字段缺失可读取，但不允许对陌生主机后台登录，用户需重新核对；无需档案或备份 schema 迁移。
- 仅补充确认而连接参数不变时，不清空扫描和候选。163 / 126 客户端标识按后端规范保持开启，使确认内容与实际连接参数一致。
- 独立只读检查没有发现剩余的凭据发送绕过路径；发现并修正了网易客户端标识规范化导致已确认参数不匹配的问题。证书验证、TLS / STARTTLS 及帮助打开错误文案未放宽或改动。

回归覆盖陌生主机无确认时在网络前拒绝、确认绑定失效、恶意域名后缀、同域 / 明确服务商兼容、旧账号可恢复、确认保存及进度保留、伪造识别响应不能自我授权、界面刷新不解除禁用。真实邮箱连通验收仍待人工执行。
